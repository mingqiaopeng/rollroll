# RollRoll 滚轮助手

一个小巧的 Windows 托盘工具：**向指定窗口持续发送滚轮**，按 `F8` 开始、再按一次停止。

- 单文件 `RollRoll.exe`（约 55 KB），不需要安装，不依赖 .NET SDK / NuGet
- 目标窗口用「拾取」确定，记住进程名 + 类名，下次启动自动找回
- 方向、速度、每步格数可调
- 速度与输入可加入拟人抖动（随机间隔 / 随机步长 / 偶发停顿）
- 两种发送方式：真实输入（默认）/ 后台消息
- 托盘常驻，全局热键，目标关闭或鼠标被移动时自动停止

## 快速开始

```bat
build.cmd
RollRoll.exe
```

1. 点 **拾取窗口**，屏幕底部出现 3 秒倒计时，把鼠标移到目标窗口上，倒计时结束后自动捕获
2. 选方向、速度与抖动档位
3. 按 `F8` 或点 **开始**

速度的单位是 **格/秒**，和「每步格数」相互独立：`8 格/秒 + 每步 2 格` 表示每秒 4 拍、每拍 2 格。面板上的「已滚 N 格」统计的是实际发出的滚轮格数，不是发送次数。

关闭面板只会隐藏到托盘；托盘图标双击可重新打开，右键菜单里有「退出」。

## 两种模式

| | 真实输入（默认） | 后台消息 |
|---|---|---|
| 原理 | `SendInput` 注入真实滚轮事件 | `PostMessage` 投递 `WM_MOUSEWHEEL` |
| 兼容性 | 最好，等价于手动滚轮 | 取决于应用是否处理窗口消息 |
| 前台 | 需要目标在前台（程序会自动切换） | 不需要 |
| 鼠标 | 会占用光标，见下 | 完全不碰鼠标 |
| 适用 | Chrome / 微信 / Office / 大多数桌面程序 | 希望静默后台滚动、且目标接受消息 |

**什么时候切到「后台消息」**：目标窗口不能被切到前台、你希望同时用鼠标做别的事、或者不希望程序动光标。Chromium 系（Chrome / Edge / VS Code / 微信内置浏览器）和 WinUI/UWP 应用经常忽略消息，此时请用真实输入。

## 拟人抖动

真实的人滚轮不会像节拍器一样匀速等步长，所以面板上有一行 **抖动** 档位：

| 档位 | 间隔抖动 | 步长抖动 | 偶发停顿 |
|---|---|---|---|
| 关 | 无 | 无 | 无 |
| 轻 | ±10% | ±15% | 约 0.1 次/秒，60–150ms |
| 自然（默认） | ±22% | ±30% | 约 0.3 次/秒，80–260ms |
| 强 | ±40% | ±45% | 约 0.6 次/秒，120–420ms |

抖动只改变节奏，不改变长跑平均速度：随机步长的小数部分会累加到下一拍，平均格数仍然等于设定值。起步的前 4 拍会略微放慢，避免「一按就开始匀速狂奔」。停顿按**每秒次数**而不是每拍概率计算，所以把速度调快时，平均速度不会被停顿拖垮。

> 拟人抖动只改善观感，**不能**用来绕过风控 / 反作弊系统。请只在允许自动化的场景使用。

## 「停靠光标」是什么

真实输入依赖系统把滚轮送到光标下的窗口，所以开始时会：

1. 把目标窗口切到前台；
2. 记住当前光标位置，把光标移到目标客户区中心；
3. 停止时把光标和前台窗口还原。

因为光标被占用，勾选 **鼠标一动就停** 后，只要检测到光标偏离停靠点 6px，本次滚动立即结束（不会和你的鼠标抢控制权）。想一边滚一边用鼠标，就取消停靠（此时需要你自己把鼠标停在目标窗口上），或改用后台消息模式。

## 热键

| 键 | 作用 |
|---|---|
| `F8` | 开始 / 停止（全局，面板隐藏时也有效） |
| `F9` | 强制停止 |
| `Esc` | 面板有焦点时停止 |

`F8` 被其他程序占用时，状态栏会提示，托盘菜单与按钮仍可用。

## 自动停止条件

- 目标窗口关闭或被最小化
- 检测到鼠标移动（仅停靠模式，可关）
- 达到最长运行时间（配置项 `MaxMinutes`，默认 0 = 不限）
- 手动 `F8` / `F9` / `Esc`

停止原因会显示在面板上，并在面板隐藏时弹一次托盘气泡。

## 配置与日志

| 文件 | 位置 |
|---|---|
| 配置 | `%APPDATA%\RollRoll\settings.ini` |
| 日志 | `%APPDATA%\RollRoll\log.txt`（超过 256 KB 自动轮转） |

配置是纯文本 `key=value`，可以直接改；写入走「临时文件 + 原子替换」，不会写坏。

## 已知限制

- **管理员窗口**：Windows 的 UIPI 会阻止普通权限进程向提权窗口发送输入/消息。程序检测到目标提权时会询问是否以管理员身份重启。
- **游戏 / 反作弊**：不适用，也不建议使用；拟人抖动不能绕过检测。
- **全屏独占 / Raw Input 应用**：真实输入也可能无效。
- **菜单、拖拽等瞬态 UI**：`WM_MOUSEWHEEL` 的坐标是屏幕坐标，拾取时建议选主窗口而不是弹出菜单。
- 多显示器负坐标已按 16 位截断处理；跨越 DPI 不同的显示器时，光标停靠点可能略有偏移。

## 构建

`build.cmd` 直接调用 Windows 自带的 .NET Framework 4.x 编译器，**不需要 Visual Studio、不需要联网**：

```bat
build.cmd          :: 编译
build.cmd /clean   :: 先删除产物
```

源码保持 C# 5 语法，便于用老编译器直接构建；`/codepage:65001` 保证中文注释与字符串按 UTF-8 读取。

### 自检

```bat
RollRoll.exe --selftest
```

会打印进程位数、`INPUT` 结构尺寸（x64 应为 40）、DPI、前台窗口、中心点解析出的滚动子窗口，并写入 `%TEMP%\rollroll-selftest.txt`。用于排查「为什么目标没反应」。

## 实现要点

- **目标解析**：从目标客户区中心开始，用 `ChildWindowFromPointEx` 逐层下钻到最深的可见子窗口（Chromium 会重建子窗口，所以每 2 秒或句柄失效时重新解析）。
- **消息编码**：`wParam` 高 16 位是带符号的滚轮增量（一格 120），`lParam` 低/高 16 位是屏幕坐标；多显示器负坐标按 `ushort` 截断。
- **节流**：后台线程 + `Stopwatch` 补偿；基础间隔按 `1000 × 每步格数 ÷ 格每秒` 计算，下限 15ms。拟人档位在此之上叠加高斯近似抖动、小数步长累加器和偶发停顿；落后于计划时重置基准而不是补帧，避免把目标的消息队列冲爆。`timeBeginPeriod(1)` 只在会话内开启。
- **安全性**：停止、目标失效、异常都汇入同一个 `Cleanup`，光标与前台窗口只在仍处于预期状态时才还原。
